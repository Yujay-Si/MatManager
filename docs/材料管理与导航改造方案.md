# 材料管理与导航改造方案

日期：2026-10-08。依据：桌面需求文档及用户确认。

## 已确认范围

左侧一级分组依次为材料管理、数据管理。材料管理包含订货、收货、付款、对账四个入口；数据管理下的数据计算保留单次、批量、历史和参数四个功能。

单价统一为元/kg；整条收货明细直接记录多个捆重量；供应商支持期初欠款及起算日期；加工进度由人工填写。共用供应商资料，不增加实际出入库、多人协作、登录或在线服务。

## 数据关系与核算

- 供应商：唯一编号、名称、起算日期、期初欠款。
- 订货：单头供应商、日期、备注；多条材质、规格、件数、单价、产品名称与备注明细。
- 收货：单头供应商、日期、备注；多条明细，各自记录多捆重量，并可关联一个订货明细。
- 付款：供应商、日期、还款、退差及备注。
- 对账：查询视图，直接从有效收货、付款计算，不另存可能过期的余额。

未收件数＝订货件数－有效关联收货件数。超额收货、跨供应商关联、收货早于订货被拒绝。有效收货所关联的订货不能作废。已作废单据保留，不能修改。

收货总重＝各捆重量相加。重量最多3位小数，单价最多4位小数。通过整数缩放计算重量×单价，每条明细金额四舍五入到分后合计，避免浮点误差。单价可为零，件数为正整数，重量必须大于零。

付款合计＝还款＋退差，两项非负且合计必须大于零。付款前后欠款由完整有效账目计算。同日单据按初次保存顺序排列，修改保持顺序；补录更早日期时自动重新核算。

期初欠款代表起算日开始前的余额。起算日及之后单据参与累计；拒绝起算日之前的单据与查询。查询期初包含查询开始日前的有效收货、付款。欠款可为负数，表示供应商预付款余额。

## 存储、兼容与安全

沿用 Electron、原生 HTML/CSS/JavaScript，不新增依赖。旧计算脚本、localStorage键名、应用用户数据目录和协议保持稳定。

新增材料数据存储于同一应用来源下的 IndexedDB `material-management-v1`。单个 readwrite 事务读取最新状态、校验并写回，避免并发窗口保存不同单据时覆盖彼此。暂存错误时取消整次操作。

材料备份包含供应商、期初和全部单据，恢复先校验完整结构及引用，再合并；重复记录跳过，同编号内容不同则整批取消。备份文件限制20 MB。所有用户文本在生成HTML时转义，CSV导出处理公式开头文本，桌面仍使用原有隔离和CSP限制。网页与桌面为不同来源，需手动导出导入材料备份迁移。
